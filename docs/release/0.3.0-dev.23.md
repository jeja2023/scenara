# Scenara 0.3.0-dev.23 发布说明

**发布日期**：2026-08-19

`0.3.0-dev.23` 是 `0.3.0-dev.22` 之后的代码质量与发布加固开发快照。本版本没有引入新的用户功能契约，而是围绕性能、安全性、可靠性、代码质量、CI 和部署一致性完成一轮系统整改，并把 Console 的解析工作台、审计浏览和模态对话框收敛为更可维护的实现。独立 `scenara-data` 服务及其生产资格证据仍不属于本仓库，必须按切流门禁独立交付和验收。

---

## 主要变更

### 1. 后端性能与可靠性

- 解析工作台对远程 Data 的**结果加载改为增量拉取**：同一 Run 复用已加载单元，仅请求新分页，避免重复全量传输。
- 流式等待增加**有界退避重试**，网络抖动或 5xx 不会立即放弃；媒体上传收敛为单路径处理，避免重复扫描与中间态泄漏。
- 结果写入改为**幂等更新**，重复交付不会产生重复结果分片；媒体上传改为 spool 到临时文件后报告真实大小，消除多部分边界处理开销。
- S3 索引批量写入与 PostgreSQL 批处理路径改为确定性顺序，移除冗余深拷贝与重复对象重建。

### 2. 安全加固

- 配额检查改为**原子化**，并发请求不再产生可用配额超卖；媒体对象、结果对象保留与吊销路径补齐。
- 解析工作台在预览帧覆盖时**显式吊销 Blob URL**，避免长时间会话中内存泄漏。

### 3. 代码质量与类型安全

- 修正若干既有损坏：`spool_upload` 缩进错位、UTF-8 BOM 混入、`useMediaPreview.ts` 编码损坏；修复 `postgres_index.py` 的 mypy 收窄错误并调整 `control_plane.py` 常量位置。
- 移除控制平面调度器空转缺口、`.strip()` 错误使用与魔数常量；`DEFAULT_BILLING_PERIOD_SECONDS` 从 import 区移到定义区。

### 4. Console 优化

- 时间轴改为**窗口化渲染**（±100 窗口 + 首/末跳转），大结果集不再一次性渲染全部单元按钮。
- 审计页支持 offset/limit **分页浏览**、空页回退与加载状态；解析与设置对话框改为原生 `showModal()`/`close()` 生命周期。

### 5. 构建与部署一致性

- `Dockerfile` 调整 **console-builder 分层顺序**：先复制清单文件执行 `pnpm install`，再复制源码，并新增分层顺序回归契约测试。
- `.dockerignore` 增加日志与孤儿 lock 文件；`python-dotenv` 声明为直接依赖，删除未使用的 `testcontainers`、`pytest-timeout` 及三个孤儿 requirements lock 文件。
- Compose 使用 `x-scenara-image` 锚点统一四个服务的镜像标签；Kubernetes 改用 `kustomization.yaml` 的 `images:` 转换器作为单一来源；默认镜像标签统一为 `0.3.0-dev.23`。

### 6. CI 去重与缓存

- `push` 触发器仅保留 `main` 分支；主测试任务排除六个安全回归文件（由独立安全任务各执行一次）并跳过集成标记，覆盖率门禁仍通过（剔除安全文件后 65.01%）。
- Web 容器构建改用 `docker/build-push-action@v7` 并启用 GitHub Actions cache，复用控制台构建产物。

## 升级说明

1. 本版本为开发快照，不改变任何公开 API 路径、SDK 调用方式或 Console 路由；`0.3.0-dev.22` 的升级与切流步骤仍然适用。
2. Compose 部署继续以 `SCENARA_IMAGE_TAG` 覆盖镜像标签（默认 `0.3.0-dev.23`）；Kubernetes 通过 `kustomization.yaml` 的 `images` 转换器覆盖。
3. 依赖声明无破坏性变更；`python-dotenv` 由间接依赖提升为直接声明，运行期行为不变。
4. CI 中主测试任务不再重复执行安全回归文件，六个安全文件由独立的 `security-tests` 任务执行一次，结果覆盖范围不变。

## 已知限制与保留决策

以下三项在整改中有意保留或部分完成，均记录决策依据，避免后续误改：

1. **内存字节输入仍需临时文件（`media_batch.py:399-404`）**：上传路径已改为 spool 到临时文件并走 `file_path`，避免内存与磁盘双份；但调用方直接传入内存字节（`media.data`）时，仍需先落盘再交给 `cv2.VideoCapture`。这是视频解码引擎需要文件路径的固有约束，仅在原始输入为内存字节时发生。
2. **`save_run` 保留 `model_copy(deep=True)`（`postgres_state.py:909`）**：该深拷贝保护调用方传入的 `RunRecord` 不被 revision 自增的副作用修改，且对象为单个运行记录而非大结果集；结果中心侧的大对象 `deep=True` 拷贝已全部移除。
3. **Compose secrets 默认挂载示例文件（`compose.yml:226-228`）**：保留 `${SCENARA_ENTERPRISE_LICENSE_FILE:-./.env.production.example}` 默认值以实现失败关闭（缺少真实许可文件时企业服务拒绝启动）；不改为 `:?` 必需形式，否则 CI 中依赖插值的 Compose 命令会整体失败。
