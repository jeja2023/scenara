# Scenara 0.3.0-dev.22 发布说明

**发布日期**：2026-08-16

`0.3.0-dev.22` 完成了 `scenara` 集成仓库一侧到独立 Scenara Data 服务的切流准备，并收敛了统一 Console 的平台主题和可访问性实现。本版本是工程开发快照，不代表独立 `scenara-data` 服务已经完成部署或获得生产资格；Data 的数据库、迁移、导入、备份恢复和领域治理能力须在其独立服务边界内实施并通过切流门禁。

---

## 主要变更

### 1. Core 到 Data 的版本化服务边界

- 新增 `DataPlatformClient` 协议、仅用于开发和迁移验证的 `LocalDataPlatformAdapter`，以及面向 `/internal/v1` 的 `HttpDataPlatformClient`。
- Core 继续持有稳定的公共 API、认证、授权、审计和 Console 入口；Dataset、Dataset Version、Annotation 与 Data 领域事实通过客户端委派给 Data。
- HTTP 客户端转发租户、项目、主体、权限范围、产品授权、请求 ID 和 `traceparent`，为每个变更请求生成稳定幂等键，并对网络错误和 5xx 响应执行有界重试。
- 远程错误以规范化错误码和原状态返回给公共 API；Core 不连接、不读取也不写入 Data 的独立数据库。

### 2. 兼容性与迁移

- 已发布 Core DTO 和 SDK 继续使用 Dataset Version 状态 `validated`、`retired`；Data 内部的目标状态 `ready`、`archived` 仅在网关边界映射，不改变公共契约。
- 新增 `scripts/export_data_migration.py`，按显式租户和项目生成不可覆盖、带 `migration-manifest.json`、对象引用、审计引用和 `checksums.txt` 的迁移包。
- 新增 [Data 切流操作说明](../strategy/DATA_PLATFORM_CUTOVER.md)，规定导出、Data 导入校验、影子读、远程模式观察、回滚窗口和本地表退役流程。

### 3. Hard Sample 与模型数据输入

- Core 仍负责反馈资格审查、导出授权、脱敏和不可变 `HardSampleManifest` 创建。
- 配置 `SCENARA_DATA_PLATFORM_MODE=http` 后，已创建清单立即幂等提交到 Data；Data 负责样本与标注创建、Dataset Builder，以及向 Model 发布 `DatasetVersionReference`。
- 本地模式拒绝把 Data 专属发布与接收行为伪装为已完成切流，避免长期双写和跨库直接访问。

### 4. Console 主题与可访问性

- Dataset/Data 路由绑定 `data-platform`，模型路由绑定 `model-platform`；主题仅覆盖受控的强调色令牌，继续复用同一 Console、登录、导航和 IAM。
- 补充跳到主内容入口、可见键盘焦点、减弱动效和移动端最小 `44px` 触控目标。
- 增加 `1440x900`、`1280x800`、`768x1024` 和 `390x844` 的 Playwright 回归，检查主题、页面可见性和水平溢出。

## 升级与切流说明

1. 开发和迁移验证可继续使用 `SCENARA_DATA_PLATFORM_MODE=local`；生产环境必须配置 `SCENARA_DATA_PLATFORM_MODE=http`、`SCENARA_DATA_PLATFORM_URL` 和 `SCENARA_DATA_PLATFORM_SERVICE_TOKEN`。
2. 先运行迁移导出器，再由独立 Data 服务导入并验证校验和、ID、状态、对象引用和摘要；使用同一租户/项目进行影子读后才允许切换远程模式。
3. Data 服务必须实现本版本约定的 `/internal/v1` 端点、服务间身份验证和幂等接收。Core 的公开 `/api/v1` 路径、SDK 调用方式和 Console 路由不变。
4. 切流观察期只允许在明确回滚窗口内恢复本地模式。窗口结束后，Core 旧数据表仅可只读；不得共享 Data 数据库或长期双写。
5. 完整 Data Hub 的原生数据治理、数据湖、标注工具、质量探索、备份恢复和生产资格证据不随本版本自动获得；这些工作由独立 Data 服务的发布流程承担。
