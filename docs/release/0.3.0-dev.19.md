# Scenara 0.3.0-dev.19 发布说明

**发布日期**：2026-08-11

`0.3.0-dev.19` 将大视频与不间断视频流处理升级为有界内存、增量推理、增量结果和连续 Stream Session 架构。有限视频与 PDF 默认处理至 EOF，实时流按时间窗口自动归档并无缝接续，不再依赖平台注入的最大解析单元限制。

---

## 主要变更

### 1. 有限媒体取消隐式最大解析单元

- 视频与 PDF 未显式提供 `max_units` 时处理至 EOF，不再从平台设置、管线目录、SDK 或控制台注入默认上限。
- `max_units` 继续保留为可选兼容字段，供旧集成迁移、测试或调用方主动设置硬边界。
- 均匀采样在未知总量且没有显式上限时保持有限视频完整处理语义；实时流使用时间窗口而不是单元数量作为主要边界。

### 2. 有界解码与增量推理

- 视频解码使用固定容量队列和批次输出，内存预算按队列容量计算，不因输入时长或未知总单元数线性增长。
- OCR 视频/流算子和人像综合分析算子改为逐批处理，不再先聚合完整 `DecodedMediaUnit` 集合。
- 未知总单元数时进度事件允许 `progress=null`，同时持续发布 `processed_units`、最新 `pts_ms` 和运行状态。
- 人像轨迹在批次之间按稳定 `track_id` 合并，保留首末时间、帧数和质量汇总。

### 3. 追加式结果分片与实时事件

- 中间结果只追加新单元到对象存储分片，避免每个批次重写完整 JSON 或完整结果索引。
- 新增 `result.delta` SSE/Webhook 事件，包含序号、单元偏移、增量数量、累计数量和结果地址。
- `GET /api/v1/runs/{run_id}/result` 分页接口只加载与请求区间重叠的分片；Python 与 TypeScript SDK 的 `get_result` / `getResult` 自动聚合全部分页。
- 保留最终 `result.available` 事件和原有结果契约，现有只消费最终结果的客户端无需修改。

### 4. Stream Session 自动续段

- 实时流按 `stream_segment_duration_ms` 形成有界 Run，默认时间窗口为 300000 毫秒。
- 同一持续流的各段 Run 归属于一个 Stream Session，并记录 `segment_index`、`previous_run_id` 和 `next_run_id`。
- 正常完成时间窗口后自动创建下一段，发布 `stream.segment.started`、`stream.segment.completed` 等事件；失败或取消不会自动接续。
- 新增 Stream Session 查询与取消 API，控制台和两套 SDK 均可跟踪或终止整个连续会话。

### 5. 大文件磁盘流式传输

- 视频上传使用分块磁盘暂存并在写入过程中执行容量检查，不再通过单个内存字节数组接收完整文件。
- 本地与 S3 对象存储实现 `put_file` / `get_to_file`，视频执行路径直接使用临时文件解码。
- 默认 `SCENARA_MAX_MEDIA_BYTES` 调整为 20 GiB；实际部署仍应结合磁盘、对象存储、网络和保留策略设置容量。

### 6. Console、SDK 与事件投递

- Console 视频模式明确显示“处理至视频结束”，视频流模式显示“自动连续分段”；兼容单元上限保持可选空值。
- 进度界面支持未知总量、累计处理单元和最新媒体时间点，并可在自动续段后跟踪下一 Run。
- Python/TypeScript SDK 的视频、文档与视频流快捷接口默认不发送 `max_units`，新增结果分页和 Stream Session 方法。
- Webhook 投递轮询与治理调度解耦，默认每秒处理待投递事件，降低增量结果通知延迟。

## 升级与兼容性说明

1. 未传入 `max_units` 的有限视频和 PDF 现在会处理至 EOF。需要旧行为的调用方必须显式传入该字段。
2. 实时流默认每 5 分钟归档一个底层 Run，并自动接续；可通过 `SCENARA_STREAM_SEGMENT_DURATION_MS` 或请求参数调整时间窗口。
3. 新客户端应订阅 `result.delta` 获取中间结果，并继续使用 `result.available` 判断当前 Run 最终完成。
4. 结果可能由多个分片组成；直接读取对象存储内部路径不是公共契约，应使用结果分页 API 或 SDK 聚合方法。
5. 镜像、Compose、Kubernetes 与离线部署的默认标签升级为 `0.3.0-dev.19`。
