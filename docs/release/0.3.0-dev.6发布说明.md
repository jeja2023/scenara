# Scenara 0.3.0-dev.6 发布说明

`0.3.0-dev.6` 是解析产品体验与结果数据底座的开发版。它把人像和 OCR 文档组织为相互独立的领域工作区，把图片、视频、文档和视频流收敛为工作区内部的数据类型，并新增跨领域的解析结果中心。用户可以在同一领域上下文中完成数据选择、参数配置、运行跟踪、当前结果查看和历史恢复，不再被迫在上传、运行和结果页面之间来回切换。

本版本仍是工程开发快照，不代表严格的 `1.0.0` 生产发布门禁已经通过。

## 解析信息架构

- 解析一级入口只展示领域，人像与 OCR 文档进入独立工作区；不再在左侧导航重复展示图片、视频、文档和视频流三级菜单。
- 领域工作区内部保留数据类型标签，并在同一页面完成当前上传或资产选择、采样参数、解析启动、进度、当前结果和同类型历史运行。
- 进入具体领域后不再重复显示人像/OCR 切换控件，页面标题、流水线和参数始终保持当前领域上下文。
- `/parse/{domain}` 与 `/parse/{domain}/{media_kind}` 作为正式入口；旧 `/portrait`、`/ocr`、查询参数入口继续兼容跳转。
- 已完成运行直接进入解析结果中心，未终态运行仍返回对应工作区，减少用户判断下一步操作的成本。

## 数据资产命名

- 用户侧“媒体”统一更名为“数据资产”，用于管理可重复使用的图片、视频、文档文件和视频流来源。
- 页面内部按“文件资产”和“视频流来源”区分资源形态，“媒体类型”统一表述为“数据类型”。
- 正式路由调整为 `/assets`，旧 `/media` 保留重定向；API 和数据库中的 `media` 技术命名暂不修改，避免无收益的破坏性迁移。

## 全局解析结果中心

- `/results` 从运行结果跳转别名升级为独立结果中心，提供领域、数据类型和关键词筛选，以及列表与详情联动浏览。
- 结果详情复用强类型 `ResultEnvelope`，展示 OCR 文本、人像对象与特征图片、解析单元、告警和原始结果信息。
- 解析工作区、运行中心与结果中心建立双向入口；结果详情可以返回对应领域和数据类型工作区。
- 结果中心是后续以人搜图、文搜图、文搜视频、人像比对等能力的统一消费入口。本版本只交付结果目录、摘要筛选和详情读取，不把尚未交付的向量召回、全文检索或比对策略声明为可用功能。

## 后端结果目录

- 新增 `GET /api/v1/results`，按租户和项目分页查询结果摘要，支持 `domain`、`media_kind` 和 `query` 筛选。
- 新增 `ResultSummary`、`ResultSummaryPage`，并扩展 `ResultReference` 的资产、来源、数据类型、资源名称、对象、人像、人脸、OCR 文本块、文本长度和告警摘要。
- Memory 与 PostgreSQL 状态后端实现相同的过滤、计数和稳定倒序语义；PostgreSQL 只生成实际启用的筛选条件，避免空参数类型推断错误。
- Run 完成后一次性生成结果引用摘要，结果列表不需要读取完整结果对象；单次详情继续使用 `GET /api/v1/runs/{run_id}/result`。
- 新增 `0005_result_center_indexes.sql`，为领域、创建时间、数据类型和资源名称查询建立索引，并在同一事务中记录迁移版本。

## 兼容性与升级

- 升级 PostgreSQL 环境时必须执行 `0005_result_center_indexes.sql`；标准 Compose 的 `migrate` 服务会自动执行。
- 新产生的结果会写入完整摘要。旧结果缺少新增摘要字段时仍可读取，界面使用运行编号和默认计数回退，但资源名称和数据类型筛选能力可能有限。
- `/media`、`/portrait`、`/ocr` 和既有解析查询参数入口保留兼容，不要求用户立即更新收藏链接。
- OpenAPI、Python SDK User-Agent、TypeScript SDK 生成类型和默认容器标签与本版本同步。
