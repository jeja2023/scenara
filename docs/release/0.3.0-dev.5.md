# Scenara 0.3.0-dev.5 发布说明

`0.3.0-dev.5` 是面向解析工作区信息架构、领域扩展、结果中心和端到端使用效率的开发版。它把解析入口组织为“领域 -> 解析工作区”，把图片、视频、文档和视频流作为页面内部的数据类型，同时增加跨领域的解析结果中心。本版本仍不是正式 `1.0.0` 生产发行版，严格发布门禁和生产模型资格要求保持不变。

## 解析工作区与导航

- 解析菜单只按领域展开，例如“人像”和“OCR 文档”分别进入独立领域工作区；媒体类型不再重复出现在左侧三级菜单。
- 新增 `/parse/{domain}/{media_kind}` 深链路并保留 `/parse/{domain}` 领域入口；同一工作区内部完成上传、数据资产选择、参数配置、运行控制、结果查看和当前数据类型历史。
- 领域菜单使用 `DomainManifest` 自动生成，新增领域不需要修改前端侧栏代码，也不向用户暴露内部领域 ID。
- 解析页增加当前领域/媒体类型上下文栏；媒体类型只在工作区下方标签中切换，避免重复入口。
- 保留 `/portrait`、`/ocr`、`/parse?domain=...` 和 `/parse?run=...` 等历史入口兼容跳转。
- 将用户侧“媒体”入口更名为“数据资产”，统一管理文件资产和视频流来源；“运行”页面继续承担运行生命周期管理。
- 新增真实的“解析结果”页面和 `/api/v1/results` 分页接口，结果中心按领域、数据类型、文件名/来源和运行编号筛选结果，支持从列表进入原始结果详情。
- 结果引用增加资源名称、数据类型、对象数量、人像数量、OCR 文本块数量、文本长度和告警数量等可检索摘要，为后续以人搜图、文搜图、文搜视频和人像比对提供统一结果索引入口。

## 运行与结果

- 解析页展示当前领域、媒体类型下的最近运行，并支持直接恢复运行上下文。
- 历史列表按领域和媒体类型收敛，避免用户在跨页面列表中重新寻找任务。
- 后端接口返回不完整或暂不可用时，前端列表统一归一化为空集合，保持可操作的空状态，不产生渲染异常。
- 动态流水线参数继续由 `parameter_schema` 驱动，新领域可以复用通用结果展示器。
- 进入具体领域后不再显示重复的领域切换控件，解析工作台保留“上传 -> 执行 -> 当前结果”的连续流程。
- 运行列表中的已完成任务可以直接进入解析结果中心，解析工作台在有结果时提供返回结果中心的快捷入口。
