# Scenara 0.3.0-dev.39 发布说明

`0.3.0-dev.39` 是一次面向全项目工程质量和生产安全的审计整改版本。版本不新增业务 API，重点修复交付阻断、契约漂移、配置分裂和误报生产能力等问题，并将平台发现类路由拆出独立边界。

## 主要变更

### 1. CI、构建与契约门禁

- 根 `package.json` 的所有工作区命令改为 pnpm 原生语法，`pnpm run check` 不再经过 npm workspace 解析；
- `console:check` 统一执行 Vue typecheck、ESLint、Prettier、Vitest 和 Vite build；
- 重新导出 `docs/openapi.json`，重新生成 `sdk/typescript/src/generated.ts` 及 `dist`，同步用户 `phone` 字段；
- 修复 OCR 产品目录中英文测试断言，新增版本、Data 认证和部署标签回归检查；
- 保持 OpenAPI/SDK drift、repository gate、release gate 和依赖审计的 fail-closed 策略。

### 2. Python 质量与类型系统

- 删除 `scenara/server.py` 中 219 个无效 `type: ignore[return-value]`，不再用失效忽略掩盖返回类型问题；
- 修复 OCR 引擎开发回退赋值、Behavior `ndarray` 泛型、Surveillance 时间来源和 face/body 模态字面量类型错误；
- 通过严格 Mypy（149 个源文件）和 Ruff 检查；
- 新增 `scenara/api/routers/catalog.py`，承载模型、领域、产品、仓库、契约和平台能力发现端点，原 URL 与响应契约保持不变。

### 3. Console 类型、安全与可维护性

- `DataTable` 改为 `T extends object` 泛型组件，表格列、格式化器、行键和行事件均传播具体行类型；
- 清理未使用导入/变量、重复类型声明、无效空 catch 和模板属性格式问题；
- OCR 版面展示从 `v-html` 改为 `sandbox=""` 的 `iframe[srcdoc]`，并设置 `referrerpolicy="no-referrer"`；
- 继续使用后端 HTML 转义，同时对宽高比例和最小展示高度做安全/布局兜底；
- 通过 Console typecheck、ESLint、Prettier、Vitest（25 项）和生产构建。

### 4. 认证、配置与 Data 边界

- Core/Data 服务间令牌统一为 `SCENARA_DATA_PLATFORM_SERVICE_TOKEN`；
- Data 独立服务未配置服务令牌时在 lifespan 启动阶段拒绝运行；
- Data 应用版本读取 `scenara_data.__version__`，避免硬编码版本失真；
- `app/settings.py` 移除旧本地认证、OIDC、JWT、RBAC 配置，避免迁移适配层形成第二认证入口；
- 移除 `admin/123456`、固定本地会话密钥等弱默认值；
- 增加错误令牌、旧令牌、无令牌启动和配置职责边界测试。

### 5. 模型治理与部署一致性

- `/api/v1/models` 仅返回状态存储中的已登记模型包，不再回退展示内置参考模型；
- `builtin_model_packages()` 明确作为开发工具参考清单，不代表已安装、已校验或已获得生产批准；
- Console 文案由“已装配模型库”调整为“已登记模型包”；
- Docker、Compose、Kubernetes、离线包脚本、Data 镜像、部署样例、README、实现矩阵和证据清单统一到 `0.3.0-dev.39` / `0.3.0.dev39`；
- 版本一致性测试覆盖 Core、SDK、Data、Docker、Compose、Kubernetes 和离线包入口。

## 兼容性与升级说明

1. 公共 `/api/v1` URL、认证方式、租户/项目上下文和响应 envelope 未改变。
2. Data 服务部署必须将 `SCENARA_DATA_PLATFORM_SERVICE_TOKEN` 同时配置给 Data 入站校验和 Core 出站客户端；旧的 `SCENARA_DATA_SERVICE_TOKEN` 不再作为兼容配置。
3. `/api/v1/models` 在未登记模型包的开发环境返回空列表是预期行为；模型必须通过正式安装和治理流程登记后才会出现。
4. 若依赖 `app.settings` 中的旧认证/JWT 常量，应迁移到 `scenara.settings` 或对应平台 API。
5. 生产配置、模型权利、固定评估集、GPU 容量、离线安装和真实 Linux 集成证据仍需单独通过发布门禁；本版本不改变 1.0 的 fail-closed 规则。
