# Scenara 0.3.0-dev.4 发布说明

发布日期：2026-08-03

`0.3.0-dev.4` 是面向迁移层收缩、容量路径、架构边界和质量证据可信度的开发版。它同时收录 `0.3.0-dev.3` 之后完成的运行结果特征图片能力。本版本仍不是正式 `1.0.0` 生产发行版；合法模型、固定评估集、目标 GPU 资格、离线安装、恢复演练、软件许可证和具名签署证据继续由严格发布门禁失败关闭。

## 本版变更

### 迁移层收缩

- 删除 116 个不被平台、测试、SDK、脚本或部署入口引用的旧 `app/` 模块，包括已退役的人像旧版路由、服务端、OIDC、PostgreSQL 适配器、流作业、图库和商业化路径。
- `app/` 从 157 个 Python 文件、约 43,364 行收缩为 43 个实际可达文件、约 6,882 行；生产镜像不再携带已退役代码。
- 拆除 `app.media`、`app.runtime` 和 `app.vision` 聚合导入产生的隐式副作用，运行路径改为直接依赖所需的预处理、后处理、向量和异常摘要模块。
- 架构测试构建 `app/` 静态引用图，并把 `scenara/`、测试、SDK、脚本、Dockerfile、部署目录和 CI 配置作为根入口；后续新增不可达迁移模块将直接失败。

### 数据库分页与容量路径

- `list_assets`、`list_sources`、`list_runs` 在存储协议中正式支持过滤、排序、偏移和数量限制；Memory 与 PostgreSQL 实现保持同一契约。
- 资产、来源和运行总数由独立 `COUNT` 查询返回；API 不再全量加载后在 Python 中过滤和切片。
- 删除资产或来源前使用数据库 `EXISTS` 判断是否存在未终态 Run，不再加载全部 Run 并逐条执行 Pydantic 校验。
- API 并发读取分页数据与总数，保持响应契约不变并缩短串行等待。
- 新增 `0004_state_list_indexes.sql`，补齐媒体创建时间排序索引以及按资产/来源查询未终态 Run 的部分表达式索引。

### 质量门禁与真实覆盖率

- `app/` 纳入完整 Ruff 和 Mypy 检查，不再只执行 `E4/E7/E9/F`；恢复全仓库 `E501` 行长规则。
- CI 覆盖率同时统计 `scenara`、`app` 和 Python SDK。当前真实结果为 11,465 条语句、62.84%，门禁设置为 60%；旧的约 81% 仅覆盖部分交付代码，不再作为质量证据。
- Python 全量回归为 150 passed、8 skipped。跳过项是需要 PostgreSQL、Redis 或 S3 兼容服务的集成测试，由 CI 的真实服务作业执行。

### 架构扩展边界

- 禁止 `scenara/domains/portrait` 以外的 `scenara` 模块导入 `app.*`；Portrait 能力快照通过领域适配器注入，`scenara/server.py` 不再直连迁移层。
- 默认 Pipeline、产品范围和模型资格证据类型由 Domain Plugin Manifest 提供，移除服务器、产品目录和反馈服务中的 Portrait/OCR 条件分支。
- 结果契约保留 Portrait 与 OCR 强类型 payload，同时增加通用领域 payload 回退，并校验顶层领域与 payload 领域一致；第三领域不再需要修改平台闭合联合才能返回结果。
- 架构测试扫描平台条件表达式中的领域标识硬编码，并验证新领域 payload 可以通过平台模型校验。

### 契约、构建产物与前端可维护性

- 新增 `.gitattributes`，强制已发布仓库契约 JSON 使用 LF；SHA-256 现在不受 Windows `core.autocrlf` 影响。
- TypeScript SDK 的 `dist/` 明确作为 npm 发布制品继续跟踪，并固定 LF；Console `dist/` 继续作为部署时生成物忽略。
- Console 引入 Prettier 3.9.6 和格式漂移门禁，全部 11 个视图完成格式化，视图最长行从 1,511 个字符降至 124 个字符。
- ESLint 保留语义规则，关闭与 Prettier 冲突的 Vue 模板缩进和闭合括号纯格式规则，消除无意义警告。

### Console 媒体与运行状态连接

- Console 的内容安全策略为 `img-src` 和 `media-src` 同时新增 `blob:`，允许本地选择的图片、视频预览使用浏览器 Blob 地址，同时继续拒绝任意外部媒体源。
- Run 事件流响应新增 `Cache-Control: no-cache, no-transform` 和 `X-Accel-Buffering: no`，避免反向代理缓存、转换或缓冲 SSE 数据。
- Console 轮询在连接被短暂中断时采用 250、500、1000、2000 毫秒的有限退避重试；业务 4xx/5xx 响应仍立即按原有错误契约处理，不会被静默掩盖。
- 调试 Compose 改用同拓扑内的 PostgreSQL 状态后端并自动执行迁移；`debug-postgres` 卷保留 Run、事件和元数据，`debug-state` 卷保留本地对象文件。容器重启仍会短暂中断 SSE/HTTP 连接，但不会清空 Run 状态；前端轮询会恢复，内联队列会按原 `run_id` 重新提交非终态 Run。
- 调试 Compose 的流地址和 Webhook 密钥改用加密对象 SecretStore，并随 `debug-state` 卷持久化；本机默认 Fernet 密钥可由 `SCENARA_DEBUG_SECRET_ENCRYPTION_KEY` 覆盖，生产环境仍必须显式注入独立密钥。
- Linux 部署脚本通过 `.gitattributes` 固定为 LF，并有部署契约测试阻止 Windows CRLF 再次破坏容器内迁移入口。

### 视频解析内存边界

- 视频解码器根据媒体尺寸、采样策略、时间窗口和预计采样单元数计算有效帧尺寸，使单个 Run 常驻的解码后 RGB 帧预算上限为 512 MiB；实际采用的最大边长写入 `media_metadata.frame_max_edge`，显式更小的调用方限制仍优先。
- `portrait.person-detection` 不再把全部采样帧一次性堆叠为 YOLO 输入；算子版本升级到 `1.1.0`，按最多 16 帧执行有界批处理并累计各批次时延指标。
- PostgreSQL 调试拓扑用原 `run_id` 恢复一段 1920×1080、662.6 秒、663 个采样帧的视频 Run：自动采用 692 像素最大边长，容器峰值 RSS 约 2.61 GiB，Run 完成且重启计数保持 0；修复前同一 Run 会顶满 15.45 GiB 并被 Docker 以 OOM/137 终止。

### 视频与实时流的实时进度和结果

- `platform.media.decode` 升级到 `1.2.0`：视频文件和实时流由后台解码线程逐单元写入有界队列，人员检测无需等待整段媒体解码完成即可开始推理；队列形成反压，并响应暂停、取消和异常清理。
- `portrait.person-detection` 对文件视频每 8 个单元发布一次结果，对实时流逐单元发布；每批推理后更新单调递增的 `Run.progress`，SSE 新增 `run.progress` 与 `result.partial` 事件，携带已处理/预计单元数。
- 部分 `ResultEnvelope` 在 Run 仍为 `running` 时即可通过现有结果接口分页读取；最新快照原子替换前一快照，旧临时对象随即删除，最终结果复用原有稳定路径与保留期契约。
- Console 收到部分结果事件后立即刷新分析单元、对象数、时间轴和特征图片，默认跟随最新单元；用户主动查看历史单元后停止自动跳转。SSE 断线时，500 毫秒轮询继续按进度变化补取快照。
- 新登记实时流不再自动请求首帧预览，避免预览和解析同时竞争只允许一个客户端的 HTTP/RTSP 流；用户从已登记列表主动选择来源时仍会按需加载预览。
- 结果页继续按完成 Run 分页展示全部媒体单元；任一含检测对象的单元均可查看裁剪图，点击裁剪图打开对应完整帧并高亮检测框。

### 运行结果特征图片

- 人像运行可按配额生成对象裁剪图和完整分析单元 JPEG，并通过 `ResultEnvelope.artifacts`、`crop_artifact_id` 和 `frame_artifact_id` 建立可追溯引用。
- 新增受运行读取权限保护的产物读取接口，以及 Python/TypeScript SDK 方法和 Console 网格、大图、高亮框、键盘切换能力。
- 产物写入采用 best-effort 语义，配额耗尽或对象存储不可用只产生告警，不改变 Run 结果；失败和取消路径清理已写入对象。
- 派生图片按 `preview` 保留期管理，并有 PostgreSQL、MinIO 集成测试覆盖写入、读取、归类、到期删除和删除后响应。

## 兼容性与升级要求

- 公开 `/api/v1` Media、Run、Pipeline、Result、SDK 契约保持向后兼容；领域 payload OpenAPI 从两个成员的闭合判别联合扩展为包含通用领域的联合。
- 已声明不兼容的人像旧版路由和 `app.server` 已物理删除。仍依赖这些内部入口的部署必须迁移到 `scenara.server` 和当前 `/api/v1` 契约。
- 使用 PostgreSQL 的环境必须在启动应用前执行 `migrations/0004_state_list_indexes.sql`；标准 Compose 迁移任务会按版本自动执行。
- 前端依赖锁新增 Prettier 3.9.6；使用 `pnpm install --frozen-lockfile` 即可获得一致工具链。
