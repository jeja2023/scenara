# Scenara 0.3.0-dev.14 发布说明

发布日期：2026-08-06

`0.3.0-dev.14` 是一次面向视频解析结果质量和运行告警语义的开发版本。本版本不改变媒体采样和模型推理覆盖范围，而是在结果构造阶段移除人像视频与实时流中的零对象单元，并让 Console 正确区分正常媒体结束与异常提前终止。

## 视频与实时流结果

- 人员检测流水线和完整人像分析流水线继续分析每个采样帧；只有模型未检测到任何对象的视频/流单元会从最终 `result.units` 中省略。
- 本次不是基于亮度、颜色或像素方差判断“空白画面”，因此不会在推理前跳过低照度、纯色背景或低对比度帧。
- 命中单元保留解码阶段生成的原始 `unit_id`、`index`、`pts_ms`、宽度和高度，过滤后不会重新编号或改写时间线。
- `media_metadata.sampled_units` 继续表示实际完成推理的采样帧数量；`result.units.length` 表示含有检测对象的结果单元数量。
- 图片媒体继续保留零对象单元，保证单张图片解析的响应结构稳定。
- 渐进式视频/流结果只发布当前已命中的单元，运行进度仍按实际处理帧数量计算，不会因过滤零对象单元而停滞。

## 告警与运行产物

- 有限视频读取到 EOF 后仍以完成状态保存 `termination_reason=source_ended`；Console 将对应告警显示为“媒体源已正常读完，本次任务已完成全部可读取内容”，不再误称“媒体处理提前结束”。
- `artifact_quota_reached` 继续表示单次运行的特征裁剪图数量达到上限。该告警不影响检测对象、时间戳或结构化结果，只会使超过上限的对象缺少 `crop_artifact_id`。
- 特征裁剪图默认上限为 `SCENARA_RUN_ARTIFACT_MAX_CROPS=200`，有效范围为 0–5000；提高配额需要同步评估对象存储容量、预览保留期和单次运行对象密度。

## 兼容性与版本

- Python 主包、Python SDK、API 系统版本和 Python SDK User-Agent 统一为 `0.3.0.dev14`。
- npm 根包、Console、TypeScript SDK、Compose/Kubernetes 镜像和离线包默认标签统一为 `0.3.0-dev.14`。
- `/api/v1` 请求字段和响应模型未新增字段；人像视频/流的 `result.units` 语义收紧为仅包含命中单元，消费方应使用 `media_metadata.sampled_units` 获取实际分析帧数。
- 本版本没有数据库迁移。已有运行结果不会被重写，过滤规则仅作用于升级后创建的新运行。

## 升级提示

1. 使用 `0.3.0-dev.14` 镜像或离线包标签部署，并确保 API、Worker 和 Console 使用同一版本。
2. 升级后重新运行需要精简结果的视频或实时流；旧结果仍保持创建时的完整单元列表。
3. 依赖逐采样帧空记录的集成应改用 `media_metadata.sampled_units` 统计分析覆盖，用 `result.units` 统计检测命中。
4. 如需完整保存对象裁剪图，按单次运行的预期对象总数调整 `SCENARA_RUN_ARTIFACT_MAX_CROPS`，并重启 API/Worker 服务使配置生效。
5. 本版本仍是开发快照，不代表 `1.0.0` 生产资格；严格发布门禁、模型制品和法律/签署证据要求继续有效。
