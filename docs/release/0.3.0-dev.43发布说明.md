# Scenara 0.3.0-dev.43 发布说明

`0.3.0-dev.43` 同时包含控制台交互质感升级与一批生产存储层缺陷修复。公开 `/api/v1` 接口契约与后端数据模型保持完全兼容；新增一条数据库迁移 `0016_trajectory_reachability_index`，只增索引不改表结构，可安全前滚。

前半部分重构了全平台 Tab 分段控制栏、优化了解析工作台布局、同步了生产环境配置模板；后半部分为五个此前零测试的 PostgreSQL 适配器补齐跨后端仓储契约，并借此修复了跨摄像头轨迹可达性误判、PostgreSQL 布控任务查询无法执行、告警幂等去重失效与生产依赖分层四类缺陷——其中两类会让对应功能在 PostgreSQL 后端完全不可用。

## 主要变更

### 控制台 Tab 切换与分段导航重构

- 全局规范化 Tab 导航体系：在 `frontend/console/src/styles.css` 中统一定义 `.tabs-header-bar`、`.domain-tabs`、`.domain-tab-btn`、`.tab-badge` 标准样式，统一支持 `<RouterLink>` 与 `<button>` 交互模式。
- 彻底解决合并页面（审计中心、模型生命周期、系统运维、智能检索、布控预警等）未定义 Tab 基础样式导致的原生超链接下划线、颜色异常及尺寸失调问题。
- 对齐**接入与权限**页面的精致紧凑设计规范：12px 字号、5px 12px 内边距、4px 按钮圆角、13px 线性图标、#eef2f1 浅灰青底槽、#ffffff 激活背景与精细微阴影。
- 解决模型生命周期因 `[data-platform="model"]` 样式污染导致的 Tab 紫色高亮问题，显式锁定全局统一的景枢青绿品牌主色（`#065e67` / `#087682`）。

### 核心解析工作区工具栏与布局优化

- 四个核心解析功能页面（人像解析、动作/行为解析、服饰解析、文字/OCR 解析）工具栏重构：将「流水线」标签与下拉选择框由上下纵向堆叠调整为**横向水平行内排列**，标签不换行并与下拉框居中对齐。
- 清理工具栏顶部冗余空白间距，工作区整体视觉向上微调贴近导航栏，大幅减少首屏空白，提升预览画板与操作区域的可视面积。

### 生产环境配置与环境模板完整对齐

- 完整对齐 `deploy/.env.production` 与 `deploy/.env.production.example`，同步最新版本镜像标签 `0.3.0-dev.43`。
- 补齐生产环境缺失配置项：`SCENARA_MAX_MULTIPART_UPLOAD_BYTES`、`SCENARA_POSTGRES_POOL_MIN_SIZE`、`SCENARA_POSTGRES_POOL_MAX_SIZE` 以及精细化 GPU 环境变量（`SCENARA_BATCH_GPU_DEVICE_IDS` / `SCENARA_STREAM_GPU_DEVICE_IDS`）。
- 移除已废弃的全局 `GPU_DEVICE_IDS` 配置；经 `python scripts/validate_production_config.py` 严格校验通过（0 错误 0 警告）。

### 代码体量与门禁体系收敛

- 优化 `scripts/code_size_gate.py` 目录遍历算法，避免递归遍历被忽略的目录提高门禁运行效率。
- `FeedbackView.vue` 的行数收敛改为把四个表格的列定义外迁到 `frontend/console/src/views/feedback/columns.ts`（视图降至 1458 行）。早先靠手工压缩列定义换取行数的做法与 Prettier 的换行规则直接冲突，会让格式检查失败。
- 移除已清理的废弃组件 `ConnectionTab.vue` 并同步更新发布门禁清单。

### 生产存储层缺陷修复与跨后端仓储契约

- **跨摄像头长期轨迹被误判为不可达**：`_transition_allows` 原先遍历候选身份的全部历史片段做行程校验，任一片段超出 `max_seconds` 即拒绝归并。行程约束只应作用于相邻两次出现——一个人先在 A、再到 B、稍后仍留在 B 时，A 与本次观测的间隔早已超出 A→B 上限却完全合乎物理。现改为经新增的 `probe_reachability` 只取窗口前后紧邻的各一条观测，紧邻观测落在本次机位时视为未发生转移。原实现另有 `limit=200` 且按 `first_seen_at` 升序取页的隐患，新探针把邻域检索下推到数据库，代价与身份历史长度无关。
- **PostgreSQL 布控任务查询无法执行**：`list_active_tasks_for_source` 使用 `SELECT DISTINCT task.document ... ORDER BY task.task_id`，该语句在 PostgreSQL 上必然抛 `InvalidColumnReference`。这是布控调度的核心路径，意味着 PostgreSQL 后端的布控功能此前完全不可用。现改写为 `EXISTS` 半连接。
- **内存后端告警幂等去重失效**：`MemorySurveillanceRepository.record_alert` 按每次新生成的 `alert_id` 判重，判重分支永不命中；PostgreSQL 侧按 `idempotency_key` 去重且有唯一约束。上游重放告警在两种后端下结果相反，现已对齐。
- **五个零测试适配器补齐契约**：`postgres_trajectory`、`postgres_surveillance`、`postgres_index`、`postgres_control_plane`、`postgres_portrait` 此前在测试目录中零引用，而生产环境跑的正是它们。参照 `tests/object_store_contract.py` 的既有模式新增五套跨后端仓储契约，由内存实现与 PostgreSQL 实现分别执行同一组断言，后端间的语义漂移会直接判定失败。上述三个缺陷都由这批契约暴露。

### 参考适配器重命名与摘要校验加固

- 三个只提供接口形状、不携带模型权重的模块改名，消除与真实生产实现的命名冲突：`fashion/production.py` → `fashion/reference_adapter.py`、`ocr/paddle_production.py` → `ocr/paddle_reference_adapter.py`、`behavior/paddle_production.py` → `behavior/paddle_reference_adapter.py`；类名与 `model_id` 一并改为 `Reference*` / `*-reference-adapter`。改名前 `ProductionFashionEngine` 同时存在于 `operators.py`（真实实现）与 `production.py`（合成输出）。
- 权重摘要校验从"不匹配只记警告后继续"改为抛 `DomainUnavailable`，与模型资产政策"生产配置严格拒绝未校验摘要"一致；合成输出分支新增一次性告警。
- 九篇开发文档的模块路径同步更新，并在每处指向参考适配器的 `SCENARA_*_ENGINE_FACTORY` 示例前加警示——这些工厂声明 `production_ready = False`，工厂加载与生产配置校验都会拒绝。

### 依赖分层校正

- `requirements.txt` 收敛回内核依赖，与 `requirements/production.lock` 的直接依赖逐项对齐。此前混入其中的 `paddlepaddle-gpu==3.0.0`、`paddleocr==2.9.2`、`paddlevideo==2.5.0` 在 PyPI 上均不存在，`uv pip compile` 会直接报 `No solution found`——CI 的第一步因此自 2026-08-23 起持续失败，锁文件也无人能再重新生成；`torchvision` 更是全仓无人引用。
- PaddleOCR 及其 PaddlePaddle GPU 运行时归入 `requirements/ocr-optional.txt`，锁定为 PyPI 可得且已验证可解析的 `paddlepaddle-gpu==2.6.2` + `paddleocr==2.9.1`；PyTorch 与 pdfplumber 归入新增的 `requirements/domain-optional.txt`；PaddleVideo 改为源码安装说明。
- 契约包制品名从 `repository-contracts-1.1.0.zip` 更正为 `1.2.0`。`CONTRACT_RELEASE_VERSION` 已是 `1.2.0`、ZIP 内部目录也是 `repository-contracts-1.2.0/`，只有 CI 的文件名与制品名滞后，下游按文件名取包会误判契约版本。

### 可观测性

补齐五处静默降级的日志：人体检测运行时加载失败后的两处回退（服饰解析退化为整图区域、行为解析退化为运动区域检测）、过期会话清理循环失败、布控绑定的流会话取消失败、PDF 原生文本层提取回退到 OCR。此前这些降级不留任何痕迹，运维无法区分"识别为空"与"根本没有模型"。

## 升级注意事项

1. 将镜像标签升级为 `0.3.0-dev.43`，Core、Data、Console 与 SDK 保持同版本。
2. 生产部署时，使用 `deploy/.env.production.example` 模板核验环境变量，确保未遗漏新增的连接池与上传门限配置。
3. 应用数据库迁移 `0016_trajectory_reachability_index`。它只在 `scenara_trajectory_segments` 上新增一个 `(tenant_id, project_id, identity_id, last_seen_at DESC)` 索引，无表结构变更、无数据回填。
4. 若此前依赖 `requirements.txt` 安装 PaddleOCR、PaddleVideo 或 PyTorch，改从 `requirements/ocr-optional.txt` 与 `requirements/domain-optional.txt` 安装。原先写在 `requirements.txt` 里的 `paddlepaddle-gpu==3.0.0`、`paddleocr==2.9.2`、`paddlevideo==2.5.0` 在 PyPI 上均不存在，本就无法安装。
5. 配置了摄像头转移时间上限（`max_seconds`）的项目，升级后跨摄像头身份归并的召回会明显上升——此前久远的历史观测会错误地否决合理的再次出现。已产生的碎片身份需要用人工合并接口收敛，迁移不会自动改写历史数据。
