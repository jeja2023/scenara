# Scenara 0.3.0-dev.42 发布说明

`0.3.0-dev.42` 是一次面向可靠性、安全边界、容量治理与控制台一致性的全面优化发布。公开 `/api/v1` 路径、请求模型和响应 envelope 保持兼容；部署侧新增的容量参数采用安全默认值，但升级生产环境前必须同步更新环境文件与反向代理配置。

## 主要变更

### 媒体上传安全与资源保护

- 图片、视频、PDF 与媒体资产上传统一改为常量内存的分块落盘流程，避免大文件被完整读入 API 进程内存。
- 新增 `SCENARA_MAX_MULTIPART_UPLOAD_BYTES`，默认 `536870912`（512 MiB）。API 会在 multipart 解析前依据 `Content-Length` 预拒绝超限请求，并在分块写入中再次按实际字节数校验。
- 超过直传上限的媒体必须使用带 SHA-256 完成校验的 S3 预签名上传流程；控制台会将 `REQUEST_BODY_TOO_LARGE` 显示为可操作提示。
- Nginx 示例的 `client_max_body_size` 已收敛到 512 MiB，必须与应用直传上限保持一致。

### GPU、队列与数据库容量治理

- Compose 的 batch 与 stream worker 默认各保留一张 GPU，不再让两个进程同时请求全部可见设备；可通过 `SCENARA_BATCH_GPU_DEVICE_IDS` 与 `SCENARA_STREAM_GPU_DEVICE_IDS` 固定应用内设备选择。
- 新增 `SCENARA_POSTGRES_POOL_MIN_SIZE` / `SCENARA_POSTGRES_POOL_MAX_SIZE`，默认每进程 `1..4` 条连接；运行时与生产配置校验会拒绝无效边界。
- `/metrics` 新增 `scenara_run_queue_metrics_up` 与按 lane 细分的 `scenara_run_queue_messages{state="lag|pending"}`，用于以 Redis Stream 堆积量驱动 worker 容量决策。
- 部署、运维基线和上线清单同步要求按“全部副本 × pool 上限”建立 PostgreSQL 连接预算，并在高并发环境使用 PgBouncer。

### 存储、模型与部署可靠性

- Qdrant 特征空间创建会在进程重启后恢复并比对持久化契约；维度、距离度量等不可变字段不再可能被重新创建流程覆盖。
- 修复 MinIO 初始化中策略 JSON 的 shell 换行错误。空白 Compose 栈已实际验证全量数据库迁移、bucket 创建、应用账号创建、最小权限策略创建和账号策略绑定。
- Compose、Kubernetes、Docker、离线包脚本、Data 服务与三套 SDK 版本统一升级到本发布版本。

### 控制台体验与可访问性

- 解析工作台新增可收起的高级采样参数、即时 OCR 文本结果展示，并修复取消任务后未持续追踪终态的问题。
- 访问管理的凭据子视图补齐 Tab 可访问性语义；修复空子路由警告。
- 清理数据集、反馈、总览、连接配置与解析工作区中的中英文混用，统一面向中文控制台的显示文案。
- 更新 Console 单元与端到端测试，桌面及移动视口覆盖上传、参数、取消、凭据签发、工作区溢出和中文界面约束。

## 升级注意事项

1. 将镜像标签升级为 `0.3.0-dev.42`，并将 Core、Data、Console 与 SDK 保持同版本。
2. 若仍需通过 API 直传大于 512 MiB 的媒体，应先评估 API 内存、临时盘和反向代理边界，再显式提高 `SCENARA_MAX_MULTIPART_UPLOAD_BYTES` 与网关上限；默认建议使用预签名上传。
3. 多 GPU 主机应为 batch 与 stream worker 做设备隔离；不要恢复为两个 worker 都请求全部 GPU 的旧拓扑。
4. 扩展 API 或 worker 副本前，按 `副本数 × SCENARA_POSTGRES_POOL_MAX_SIZE` 复核 PostgreSQL 连接预算。
