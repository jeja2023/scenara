# Scenara 0.3.0-dev.0 发布说明

发布日期：2026-07-30

`0.3.0-dev.0` 是产品矩阵与统一访问底座的开发快照，对应 Python 版本 `0.3.0.dev0`。它不是正式 `1.0.0` 生产发行版，也不改变严格发布证据门禁。

## 主要内容

- 增加 Scenara Parse、Model、Data、Edge、Flow、Search、Agent、Console、API、SDK 与 Index 的统一产品目录和成熟度契约。
- 增加版本化仓库拓扑契约，正式确定当前仓库为平台集成仓库、已有训练仓库为 Model 专业仓库、Data 在治理门禁成熟后独立建仓。
- 将模型制品准入、部署反馈、难例交接和数据集版本输入升级为 `1.0.0` 正式跨仓库契约：独立 JSON Schema、有效示例、发布清单、SHA-256 发布锁、确定性 ZIP 制品和向后兼容门禁齐全。
- 新增 `POST /api/v1/model-packages/admissions`。模型清单必须使用不可变制品、模型卡和评估证据引用，并显式绑定受信运行时配置；禁止通过模型包上传可执行代码。
- 模型激活与回滚现在按租户、项目和能力切换唯一运行时绑定；Run 启动时冻结绑定，现有 Portrait ONNX 运行时按该绑定选择精确模型版本与摘要。
- `ModelDeploymentEvent` 进入 `model.deployment.changed` Webhook Outbox，复用签名、重试、死信和投递回执，将平台部署结果回传训练仓库。
- 增加 Organization、Project、User、Role、Membership、Service Account、API Key 与 Product Entitlement。
- 增加平台根令牌与服务账号 API Key 双认证入口，以及 scope 收窄、产品授权交集、撤销、过期和账号停用检查。
- 增加内存和 PostgreSQL IAM 仓库、Console 管理界面、Python/TypeScript SDK 与 OpenAPI 契约。
- Console 建立中文优先设计契约和统一标签层；产品说明、访问能力、状态、授权来源、运行错误与告警均使用中文展示，专有技术名称除外。
- Console 总览增加仓库拓扑，完整展示三个仓库的负责、不负责、下一道门禁、跨仓库契约和强制边界；Python/TypeScript SDK 同步增加拓扑查询方法。
- TypeScript 生成器为公开的 OpenAPI SHA-256 摘要写入精确密钥扫描豁免，消除 `secret-scan` 误报且不放宽其他扫描规则。
- 启用蓝紫青双曲面带与中心四向星组成的新品牌标志，同步 Console、favicon、应用图标、单色版及横竖字标，并更新品牌资产使用规则。

## 升级步骤

1. 将应用、Console 和 TypeScript SDK 制品切换到 `0.3.0-dev.0`；Python 主包与 Python SDK 使用 `0.3.0.dev0`。
2. 在启动 API、Worker 和 Scheduler 前运行既有迁移任务。已有数据库会依次保留 `0001_initial.sql`，执行 `0002_access_foundation.sql` 和 `0003_model_runtime_contracts.sql`；后者将 active 唯一约束从模型标识升级为能力绑定，并保留历史模型包和部署事件的可读性。无法证明运行时绑定的旧模型包会进入保留的 `legacy/` 命名空间，不参与实际切换；需要以新版本正式准入后再激活。
3. 保持现有 `SCENARA_API_TOKEN` 作为引导凭据；需要最小权限自动化访问时，在 Console 或 API 中创建 Service Account 和一次性 API Key。
4. 为项目显式配置需要启用的 Product Entitlement，再将服务账号和 API Key 限制在相应产品及 scope 内。
5. 运行 `/livez`、`/readyz`、IAM 库存、产品目录、仓库拓扑、正式契约目录、模型准入/激活和部署反馈 Webhook 的冒烟验证。

## 兼容性

- 本版本没有移除已有 `/api/v1` 接口；新增契约目录集中在 `/api/v1/platform/*`，模型准入使用 `/api/v1/model-packages/admissions`。
- `ModelPackageManifest`、`ModelRelease` 和 `ModelDeploymentEvent` 增加运行时绑定与摘要字段。模型准入是新增接口，不接受缺少正式 `1.0` 字段的非版本化清单。
- 平台根令牌请求头行为保持兼容。服务账号 API Key 的租户、项目、主体、scope 与产品范围从凭据派生，不能由请求头覆盖。
- 新数据库对象通过增量迁移添加；回退应用版本时应保留 `0002` IAM 表和 `0003` 模型能力字段/索引，避免破坏已签发凭据、IAM 数据和激活绑定。若要停用新访问路径，应先撤销 API Key，再将部署镜像标签切回先前版本。
- 默认 Compose 与离线包镜像标签已改为 `0.3.0-dev.0`，仍可通过显式 `SCENARA_IMAGE_TAG` 选择经过批准的旧制品。

## 已知边界

交互式用户登录、OIDC/SAML/SCIM、登录时角色解析、套餐配额与账单、资源停用和审批、集中审计导出，以及 Model/Data/Edge/Index/Search/Flow/Agent 的完整独立产品闭环尚未完成。现有模型训练仓库的实际远程地址仍由组织级配置绑定；Data 独立仓库尚未创建。详细范围见 [产品矩阵](../strategy/产品矩阵.md)、[仓库拓扑](../strategy/仓库拓扑.md)、[访问底座](../strategy/访问底座.md)和[实施矩阵](实现与验收矩阵.md)。

## 验证摘要

- Python：97 passed，默认跳过 6 项真实服务集成测试，覆盖率 79.05%；Docker PostgreSQL/pgvector、Redis 与 MinIO 环境中 6 项集成测试通过。
- Console：桌面 Chrome 与 Pixel 7 共 30 项 Playwright 验收通过，包括仓库职责展示、后端英文文案隔离和横向溢出检查。
- Ruff、Mypy、前端检查与构建、Python/TypeScript SDK、OpenAPI 生成漂移、仓库门禁和实现门禁通过。
- 严格正式发布门禁仍因缺少法务、模型、目标硬件、离线和具名签署证据而按设计保持关闭。
