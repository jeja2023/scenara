## 3. 已补齐的仓库内任务

### 3.1 `scenara-data`

- 独立仓库已实现 Dataset、Dataset Version、Sample、Annotation、Quality、Lineage、Hard Sample、Builder、Provider、IAM/审计、Outbox、对象存储和迁移导入。
- 真实 Data API 使用 `/internal/v1/`，公共工作台登录不替代 Core IAM；跨仓库对象只通过已发布契约、事件和 SHA-256 引用传递。
- 独立仓库的 PostgreSQL 迁移为 `migrations/0001_initial.sql` 与 `0002_hard_sample_manifests.sql`；根仓库的 `migrations/data/0001_data_domain.sql` 仅用于兼容适配器和迁移验证。
- 迁移导入保留源 ID、作用域和摘要，支持失败报告与幂等重放；真实生产迁移、影子读和恢复报告仍属于外部资格任务。

### 3.2 `scenara`

- 保留 Core 对外 `/api/v1` 路径和 SDK，Dataset/Annotation 的远程模式继续由 `HttpDataPlatformClient` 承担。
- Core 不新增训练、实验、数据集事实来源或跨仓库数据库访问。
- Data 版本引用的兼容字段由 Core 网关隔离，避免进入正式契约模型。

### 3.3 `scenara-contracts`

- 当前以 `contracts/repository/v1.0.1/` 为发布事实来源，并继续将 `v1.0.0` 作为只读历史目录。
- Schema、有效示例、Manifest 摘要、发布索引和确定性 ZIP 由现有契约门禁锁定。

### 3.4 `scenara-model`

- 独立仓库已具备 Training Job、Experiment、异步流水线、任务日志、Dataset Version 输入校验、训练/导出/评估 Adapter、Model Package、Registry、Release Approval 和 Rollout API。
- 生产训练强制校验 `dataset-version-input` 的授权、版本、UTC RFC3339 时间和 manifest SHA-256；Smoke Adapter 不得被标记为生产制品。
- 当前仍保持 `seed`，因为 FastReID 固定评估、真实模型权属、Core 统一 IAM/Console 和 `deployment-feedback` 正式消费尚未形成跨仓库生产证据。

## 5. 依赖与停止条件

1. `DATA-M8` 依赖 `DATA-M3`、`DATA-M5`、备份恢复和独立服务凭据全部通过；未通过前 Core 只能使用本地兼容适配器进行开发或迁移验证。
2. `MODEL-M1` 至 `MODEL-M3` 必须由独立 `scenara-model` 仓库负责；Core 不得以本地模型卡、ONNX fallback 或运行时绑定代替训练和评估证据。
3. `CORE-Q1` 和 `CORE-Q2` 是发布门禁，不是可以在代码仓库内“补齐”的模拟任务。缺证据时版本最多标记为开发版或内部验证版。
4. `scenara-contracts` 的已发布 `v1.0.0` 和 `v1.0.1` 目录均不可原地修改。任何不兼容变更必须发布新主版本，兼容新增必须发布新次版本并运行 `--against` 检查。
5. 四个仓库不得共享数据库表、源码导入、未版本化接口或本地文件路径；跨仓库只允许版本化 API、事件、生成 SDK 和不可变对象引用。

## 6. 执行顺序

```text
Contracts v1.0.1 锁定（v1.0.0 历史目录不可变）
    -> Data PostgreSQL/对象存储迁移与影子读
    -> Dataset/Annotation/Quality/Lineage 正式领域表
    -> Hard Sample -> Dataset Version E2E
    -> Model Training Job -> Evaluation -> Model Package
    -> Core Admission -> Deployment -> Runtime -> Feature -> Search
    -> 目标环境资格与正式切流
```

每个里程碑完成后更新本文件的状态、责任人、变更版本和证据路径；没有证据的条目保持原状态，不得删除或改写为“已完成”。
