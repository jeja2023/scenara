# Scenara Parse 媒体产品标准

## 状态

- 版本：1.2
- 日期：2026-08-11
- 范围：图片、视频文件、PDF 文档、实时视频流的接入、解析、运行、结果、控制台、SDK 与运维证据。

## 产品基线

Scenara Parse 采用统一的 `Media -> Run -> Pipeline -> Result` 契约。图片可以使用同步等待的快捷入口；视频和实时流必须创建可恢复查询的异步 Run。任何输入类型都不得绕过租户、项目、权限、审计、保留和模型来源边界。

当前标杆能力取自公开的官方产品资料：Amazon Rekognition Video 使用可创建、启动、查询、停止和删除的流处理器，并将结果投递到持久消息或通知通道；Azure AI Video Indexer 同时覆盖上传视频和实时流，强调时间戳、边框、场景、镜头、关键帧、OCR 与检索；NVIDIA DeepStream 强调多路实时管线、解码、推理、跟踪、元数据和可观测性。Scenara 不复制云厂商绑定能力，但采用相同的产品原则：显式生命周期、可定位时间轴、结构化元数据、异步结果、故障可见和安全的源管理。

官方资料：

- Amazon Rekognition Video streaming processors: https://docs.aws.amazon.com/rekognition/latest/dg/streaming-video.html
- Azure AI Video Indexer overview: https://learn.microsoft.com/azure/azure-video-indexer/video-indexer-overview
- NVIDIA DeepStream documentation: https://docs.nvidia.com/metropolis/deepstream/dev-guide/text/DS_Overview.html

## 必须满足的能力

| 能力面 | 图片 | 视频文件 | 实时流 |
|---|---|---|---|
| 输入 | 文件上传 | 文件上传 | RTSP、RTMP、HTTP、HTTPS 源登记 |
| 接入校验 | 内容解码、像素限制、格式记录 | 容器/首帧探测、尺寸与时长记录 | URL、DNS、SSRF 策略和连接前复验 |
| 处理 | 单单元 | 间隔、均匀、解码关键帧、场景切换及时间窗口 | 同一采样策略、有限重连、连接/读取超时 |
| 生命周期 | 快捷等待或异步 Run | 异步 Run，默认处理至 EOF，可查询、暂停/恢复、合作式取消 | 独立队列通道，按时间窗口自动归档并接续同一 Stream Session |
| 结果定位 | `frame_0` | 稳定帧号与解码器 PTS/媒体位置 `pts_ms` | 跨重连严格单调的作业时钟 `pts_ms` |
| 控制台 | 预览、运行、结果叠加 | 播放、采样参数、时间点结果 | 源登记、参数、状态和结构化结果 |
| 可追溯性 | SHA-256、模型、流水线 | SHA-256、媒体元数据、模型、流水线 | 脱敏源、终止原因、模型、流水线 |

## 质量门禁

1. 无效或声明类型不一致的媒体必须在资产创建时失败，不能到运行阶段才暴露。
2. 视频文件必须处理至 EOF 或调用方明确指定的时间终点，PDF 文档必须处理全部页面；任何解析入口都不得按单元数、帧数或页数截断输入。实时流使用时间窗口分段形成连续 Stream Session，单段边界不得限制会话的连续解析。
3. 流地址中的凭据、查询参数和片段不得出现在 API、日志、事件或控制台中。
4. 每个结果单元必须包含稳定标识、索引、尺寸及视频时间点；结果必须保留媒体处理摘要和终止原因。
5. 控制台不得只提供资产登记；三类媒体必须能直接发起解析、观察状态、取消任务并查看结果。
6. Python SDK、TypeScript SDK、OpenAPI 和控制台类型必须与服务契约同步。
7. 图片、真实视频样本、模拟断流重连、源安全策略和控制台三模式必须有自动化测试。
8. 正式发布必须通过后端单测、集成契约、前端检查、桌面与移动端 E2E、OpenAPI/SDK 漂移检查和仓库发布门禁。
9. 正常解码的关键帧判定必须使用最近解码帧类型；只适用于 FFmpeg raw mode 的 `CAP_PROP_LRF_HAS_KEY_FRAME` 不得用于抽帧。
10. 长算子执行期间必须持续同步 Run 状态到线程安全控制对象；暂停时不能继续读取，取消时必须在当前有界读取返回后释放捕获器。
11. 控制台事件流必须继承普通 API 的基地址、认证、租户和项目上下文，并在断流时保留轮询接管。
12. 快捷解析入口省略流水线版本时由服务端解析唯一的 active 版本；需要可复现绑定的调用方必须显式传入版本。控制台和 SDK 不得复制服务端默认版本常量。
13. 图片、视频、文档与流入口必须在产品目录中显式列出；文档响应使用独立的 `ParseDocumentResponse` 公共契约。
14. 视频与流的中间结果必须按追加分片保存，并通过 SSE/Webhook 发布 `result.delta`；结果分页只读取与请求范围重叠的分片。
15. Stream Session 的每段 Run 必须记录 session、段序号和前后 Run 引用；正常到达时间窗口后自动创建下一段，失败或取消不得自动接续。

## 明确边界

- 实时流以连续 Stream Session 对外呈现；每个底层 Run 仍是有界时间窗口，便于资源调度、故障隔离、日志审计和结果归档。
- 解析工作台会持续跟踪 `pausing`、`paused`、`cancelling` 等中间态，并提供暂停、恢复和取消操作；只有终态才停止事件与轮询跟踪。
- OpenCV 后端若不提供已解码帧类型，`keyframe` 策略必须明确失败，不能退化为接受全部帧；若不提供 decoder PTS，则显式回退到媒体位置时间戳并在 `timestamp_source` 中记录。
- 单次底层 `read` 的取消上界受配置的读取超时约束；需要强制立即终止不可信解码器时，应升级为独立进程或 GStreamer/DeepStream 隔离方案。
- RTSP/RTMP 浏览器预览依赖正式 HLS/WebRTC 网关；在此之前控制台只显示脱敏源信息和服务端解析结果。
- 语义能力取决于已安装并通过治理门禁的模型。媒体解码成功不等于生产模型就绪。
- 音频转写、跨视频语义搜索、场景摘要和多摄像头融合属于独立能力门禁，不能从基础视频抽帧能力推断为已实现。
